# 审查轴 · 原子定义

本文件是 `adversarial-review` 的轴字典。**逐条照做，不得凭印象简化。**

---

## 一、为什么是这 5 个（封闭性证明）

对「一个已经存在的东西」的全部合理批评，形式只有四种：

| 批评形式 | 含义 | 归属 |
|---|---|---|
| **缺** | 它没做到它说做到的 | D1 |
| **缺** | 它没做到你以为它该做到的 | D2 |
| **错** | 它做了，但在某些条件下给出错误结果 | D3 |
| **冗** | 它做了，但有等价且更省的做法 | D4 |
| **增** | 它做了且成立，但有几乎白捡的增量没拿 | D5 |

完备性（D1/D2）· 正确性（D3）· 必要性（D4）· 充分性（D5）——这四者构成对一个「已存在的解」的全部评价维度。**这是分析命题，不是经验分类**：不存在第 6 种批评形式，因为再没有第五个可被质疑的属性。

「无枝叶」由此成立：每轴只有一个判定问句，再往里拆就是在重复它自己。

## 二、五个原子轴

### D1 · 断言之缺

| 字段 | 内容 |
|---|---|
| **唯一判定问句** | 作者声称完成的事，证据在哪？ |
| **证据形态** | 断言 → 产物位置的映射（`文件:行` / 命令回显 / 页面元素 / 输出片段） |
| **升级门槛** | 任一断言找不到可指认的落点 → defect；若该断言命中用户核心诉求 → 进 BLOCK 候选 |
| **边界（不归我管）** | 需求本身该不该做（→ D2）；功能存在但在条件下出错（→ D3） |

**识别信号**：作者用了「已实现 / 已覆盖 / 已修复 / 已支持 / 已对齐」这类完成时动词。

---

### D2 · 期待之缺

| 字段 | 内容 |
|---|---|
| **唯一判定问句** | 用户没被明说、但按常识会期待的东西，在哪？ |
| **证据形态** | 原始诉求**逐条**对账表（原文条目 → 落点 / 显式排除 / 无） |
| **升级门槛** | 任一条目无落点，且作者从未书面声明「不做」→ defect |
| **边界（不归我管）** | 作者已明确排除并给了真实理由的范围；纯属 reviewer 个人偏好的加戏 |

**判据句**：用户看到成品会说「这怎么没有？」→ D2。说「哦，还能这样」→ D5。

**关键**：对账表必须基于**用户原话**，不能基于作者的转述。转述即污染。

---

### D3 · 失效之径

| 字段 | 内容 |
|---|---|
| **唯一判定问句** | 在什么输入 / 状态下，它会给出错误结果**且不自曝**？ |
| **证据形态** | 触发条件 + 具体错误结果 + 使用者为何察觉不到 |
| **升级门槛** | 存在静默错误路径（错而不报警、错得看起来正常）→ **无条件 BLOCK** |
| **边界（不归我管）** | 会当场报错的失败（那只是鲁棒性建议，归 D5）；性能不够快（归 D4/D5） |

**这是唯一一条能单独触发 BLOCK 的轴。** 因为其他四条都是「不够好」，只有它是「有害」。

**审查动作**：不要问「考虑了边界情况吗」（无意义）。要问具体的：
- 空输入 / 超长输入 / 并发 / 超时 / 部分失败 / 重复提交 / 权限不足 / 编码异常
- 数据从哪来、脏了会怎样、谁在消费它的输出
- 重跑一次会怎样（幂等性）

---

### D4 · 替代之疑

| 字段 | 内容 |
|---|---|
| **唯一判定问句** | 有没有等价但更简单 / 更标准 / 更便宜的做法？ |
| **证据形态** | 一个**可执行**的替代方案 + 它省掉什么 + **它的代价**（缺代价的方案不算 finding） |
| **升级门槛** | 替代方案在同等约束下成立，且总代价更低 → 当前实现失去必要性 → defect；否则 observation |
| **边界（不归我管）** | 单纯「我更喜欢」的品味差异；需要改变需求才能成立的方案 |

**代价必须写。** 这是防「键盘架构师」的唯一闸门：只谈收益不谈代价的替代建议，直接作废。

**同时覆盖过度设计**：「这东西根本不需要」也走这条轴——必要性存疑。

---

### D5 · 未取之值

| 字段 | 内容 |
|---|---|
| **唯一判定问句** | 方案成立的前提下，有哪些**低代价**价值被漏掉？ |
| **证据形态** | 具体增量 + 成本量级（行数 / 分钟 / 一次命令） |
| **升级门槛** | 增量成本 ≤ 现有实现的 10%，且收益能被一句话命名 → 记 debt；否则不记 |
| **边界（不归我管）** | 需要重构才能拿到的价值（→ D4）；用户根本没期待的东西（→ 也可能只是噪音，慎记） |

**这是唯一不会产生 defect 的轴。** 它只产 debt，因为「没做到更好」不是过错。

---

## 三、归轴冲突裁决

一条 finding 想落两个轴时，按此顺序裁决，**只记一次**：

1. **D3 优先**：只要能构造出「错而不报警」，它就是 D3，其他轴让位。
2. **D1 优先于 D2**：作者声明过的，先算 D1。声明过却没做，比没声明更严重。
3. **D4 优先于 D5**：需要重做结构的归 D4；在现有结构上叠加的归 D5。
4. **D2 优先于 D5**：用户会问「这怎么没有」的归 D2；只是「还能更好」的归 D5。

被让位的轴，可在主 finding 里加一行 `↳ 交叉: D<n>`，但不单独计数、不单独挂反诘。

---

## 四、AXIS-MISS

出现装不进五轴的问题时：

- 不硬塞、不扩轴。
- 记一条 `M1 · <问题> · 建议新轴: <名>`
- 同时在结论里说明：**这是本框架的一个已知缝隙**，不是本次审查的失败。
- 只有出现 ≥3 次同类 AXIS-MISS，才考虑扩轴（且要用户确认）。

这条逃逸舱的存在，是「封闭」能成立的前提——假装穷尽比承认边界更危险。
